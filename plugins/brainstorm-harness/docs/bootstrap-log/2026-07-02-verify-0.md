# Brainstorm Harness bootstrap log: verify #0 (2026-07-02)

> ライト版ハーネスエンジニアリングの「要検証ポイントをインラインで潰す」パス。設計の技術前提を Claude Code v2.1.198 の挙動に照らして確認した結果。claude-code-guide エージェントによるドキュメント照合＋不確実性フラグ付き。

## 確定事項（設計に反映済み）

| # | 論点 | 結論 | 設計への影響 |
|---|---|---|---|
| V1 | SessionStart フックの stdout はユーザーに画面表示されるか | **不確実**。「文脈へ注入される」とは明記されるが画面表示は保証されない | バナーは **起動スクリプト `clbs-run` が `claude` 起動前に echo** する（フック依存をやめる） |
| V2 | `--settings` のマージ挙動 | **キー単位の上書き（ディープマージではない）**。`enabledPlugins` を渡すとオブジェクトごと置換。omit したキーはファイル値を維持。優先順位は Managed > `--settings` > local > project > user | オーバーレイに **ONにしたい厳選プラグインだけ列挙**すれば、未列挙は落ちて無効化。`theme`/`permissions`/`statusLine` も確実に上書き |
| V3 | statusLine はプラグイン有効化で自動反映されるか | **されない**（プラグインは template を同梱できるがユーザーが自分の設定で有効化する必要） | statusLine は **オーバーレイ `brainstorm.json` で明示指定**（絶対パスを setup.sh が解決） |
| V4 | プラグインのフックは自動反映されるか | **される**（plugin `hooks/hooks.json` はユーザー設定へマージ） | SessionStart の「英語・ブレスト前提で温かく挨拶」はプラグインのフックでOK |
| V5 | 1つの marketplace.json で複数プラグイン可か | **可**。`plugins[]` に各 `source`（相対パス/GitHub/npm）。marketplace.json 必須= `name`/`owner`/`plugins`。plugin.json 必須= `name`/`description`/`version` | アンブレラ `tech-teku-toolkit` 構成が成立 |
| V6 | 友達側フロー | `/plugin marketplace add <owner>/<repo>` → `/plugin install <name>@<marketplace>`（CLI 版も可） | README にこの手順を記載 |
| V7 | `wt.exe -w new -p "Name"` + WSL commandline | **確認**。`commandline: wsl.exe -d Ubuntu -- bash -lic "..."`、内側は `\"`。空白名は要クオート | 設計どおり |

## 未確定（実装時に潰す）

- **T1 `theme` の有効値**: 公式ドキュメント非記載。`"light"` が有効かはローカル `/config` で要確認。代替: 有効でなければ `light-daltonized` 等の light 系、または `auto`（ターミナル自体が明るいので実害小）。
- **T2 WT プロファイル名の絵文字**: 未検証 → ASCII `Brainstorm` を採用し、🌱は `tabTitle`/`icon` で付与（回避済み）。

## メモ
- オーバーレイで `hooks` キーを omit すれば、既存のグローバルフック（cux 各種・ccstatusline）は維持される（キー単位上書きのため）。statusLine だけ差し替わる。
- bypassPermissions はブレスト窓（ユーザー明示起動）に限定。グローバル設定は不変（オーバーレイのみ）。
