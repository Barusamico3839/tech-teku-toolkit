## 確認された指摘 → 修正（テーマ別）

### 統治（最重要3件）

1. **[high] CI の version-bump ゲートが push 時 `|| true` で無効化**、HEAD~1 比較は複数コミット push をすり抜ける（隔離repoで実証）→ `|| true` 削除、基点を `github.event.before`（全ゼロSHA/未fetch時は origin/main フォールバック）に変更。version-bump-check.sh の rev-parse ガードも `^{commit}` に強化（任意の40桁hexが素通りしていた・実測）。
2. **[high] 発芽時に blueprint キャッシュを manifest.json と照合しない** — 改竄済みキャッシュがそのまま planted.json の信頼ベースラインに焼き込まれる（隔離環境で再現: 汚染 philosophy が pristine 扱いになり全ゲートが永久パス）→ 発芽に**整合ゲート**を追加: walk した hash 辞書と manifest["files"] の**双方向等値**（rogue 追加ファイルも検知）＋ manifest.seed_version == plugin.version。不一致は「tamper または壊れたリリース」として発芽中止。
3. **[medium] check-invariants.sh が roots/ への「ファイル追加」を検知しない**、roots/manifest.json が hash 対象外 → planted.json に manifest.json を含める（skip 削除）＋チェッカーに roots walk（planted 未記録ファイル = fail）。両方同時でないと新規発芽が壊れる点まで検証者が特定済み。

### 発芽スキルの堅牢化

4. **[medium] コミット trailer が複数 `-m` で別段落になり機械可読でない** → 単一 `-m` 内のリテラル改行で1段落に（germinate/personalize/scout の全コミット）。
5. **[high(acceptance)] leaf/declined マーカーが cwd 相対で書かれる** — サブディレクトリ起動で間違った場所に、発芽直後は `cd` の残留で seedling 内に leaf が作られ e2e が壊れる → `cd` 全廃（git -C / 絶対パス化）、`PROJECT_ROOT="$(git rev-parse --show-toplevel 2>/dev/null || pwd)"` を**各 bash ブロック冒頭で再導出**（シェル変数はブロック間で保持されない）。
6. **[low(robustness)] クラッシュセーフでない** — planted.json 存在を冪等性の番兵にすると半端な seedling が恒久的に「発芽済み」扱い → 番兵を **germinate コミットの存在**に変更、planted/index/leaf は tmp→mv の原子的書き込み、leaf-only パス冒頭で invariants 自己チェック。
7. **[medium(coherence)] 2プロジェクト目で trend-stock 再提示・hardening 再提案が走る** → leaf-only パスは「step 4 のみ・STOP」を明文化。

### ドキュメント整合

8. **[high(coherence)] SECURITY「settings.json を変更しない」と skill 手順6「deny ルール追加」が矛盾** → 手順6を「diff 提示のみ・適用はユーザーの手」に統一（SECURITY.md も同語に）。
9. **[medium] フックが P1 に存在しない trend-stock/summary.md を毎セッション参照させる** → フック文言に index.json フォールバックを追加 ＋ 発芽時に summary.md スタブを生成（curated view の初期化を前倒し）。
10. **[low] README が CLAUDE_CONFIG_DIR 導出に触れない** → 表記規約ノートを1行追加。
11. **[low] spec §3 ツリーに index-seed.json が無い** → 追記。
12. **[low(acceptance)] フックテストの欠落セル leaf×clear** → 追加（24ケースに）。

## 学び（メタ）

- **検証者に「隔離環境で再現せよ」と明示すると指摘の質が跳ね上がる**。#3 の確認済み14件は反証 0 — findings が実測ベースだと refute 率が下がる（#2 は 3/30 反証）。
